# 决策记录

格式：`D-xxx 标题 — 决定 / 理由 / 代价 / 日期`

- **D-001 翻译引擎默认 Apple Translation**
  - 决定：默认引擎是 Apple Translation（本机离线）。
  - 理由：Lipper 明确说"不需要翻译很准，Apple 自带的就很好"；零网络、零依赖、零费用。
  - 代价：口语和俚语较弱，用 glossary 弥补。其它引擎留作 S3，默认关闭。
  - 日期：2026-10-10
- **D-002 MVP 用贴靠侧栏，不做气泡内嵌**
  - 理由：侧栏只依赖窗口 frame，稳；内嵌依赖每个气泡的 frame 和滚动同步，脆。
  - 安排：内嵌做成 S1。
  - 日期：2026-10-10
- **D-003 不引入第三方 Swift 包**
  - 理由：减少供应链和审查负担，便于开源。
  - 日期：2026-10-10
- **D-004 kmsg 只读子集 vendor 进 Sources/KakaoAX**
  - 决定：不作为依赖引入整个 kmsg。
  - 理由：kmsg 含发送、登录等自动化路径，与本项目只读红线冲突。
  - 日期：2026-10-10
- **D-005 开发期隐私：AI 只看脱敏数据 + 标题白名单的 나와의 채팅**
  - 日期：2026-10-10
- **D-006 只翻可见消息**
  - 决定：不回溯历史，翻译范围由可见集合驱动。
  - 理由：AX 列表可能虚拟化；只读约束下也不能主动滚动。
  - 日期：2026-10-10
- **D-008 单一测试 target + CLT 下的 swift-testing 路径**
  - 决定：所有测试放在一个 test target `TalkLensTests`（子目录 Core / KakaoAX / Translate）。Package.swift 在检测到 `/Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing` 时，给测试 target 加 `-plugin-path` 和 Testing.framework 的 rpath。
  - 理由：本机只有 Command Line Tools，默认构建系统找不到 `TestingMacros` 插件和 `Testing.framework`，`@Test` 无法展开。另外 swift-testing 每个测试 bundle 各打印一行 `Test run with N tests`，verify.sh G3 取的是最大值而不是总和，分成多个 target 会少算。合成一个 target 后不需要改 verify.sh。
  - 代价：`unsafeFlags` 只对根包有效（本项目就是根包，没问题）；装了 Xcode 的机器上这个分支不生效。
  - 日期：2026-10-10
- **D-009 `.axjson` 的 root 是整个聊天窗口子树**
  - 决定：fixture 的 `root` 存聊天窗口（AXWindow）整棵子树，而不只是 transcript 的 AXScrollArea。
  - 理由：这样 TranscriptLocator（找输入框和消息区）也能在 replay 和单测里跑到，回归覆盖更完整。
  - 代价：文件更大；录制时要限制深度和节点数（≤ 40 层、≤ 8000 节点）。
  - 日期：2026-10-10
- **D-010 用"切段翻译 + 拼接"保护 URL 和 @提及，不用占位符**
  - 决定：ChatPreprocessor 把消息切成 `MTSegment`：URL、`@提及`、换行是 `.keep`，其余是 `.translate`；长段按句切到 ≤ 1000 字。只翻 `.translate` 段，再按原顺序拼回。
  - 理由：架构草案里的占位符方案要先实测 Apple 翻译能否原样保留占位符，现在翻译语言还没装，没法测；切段方案不依赖引擎行为，更稳。
  - 代价：句子被 URL 截断时，两边分开翻，语序可能略生硬。
  - 日期：2026-10-10
- **D-011 KakaoAX 依赖 TalkLensCore**
  - 决定：KakaoAX 的解析器直接产出 TalkLensCore 的 `ParsedMessage`。
  - 理由：避免再定义一套中间模型；TalkLensCore 是纯 Foundation，不会把 AppKit 带进来。
  - 日期：2026-10-10
- **D-012 self-chat 录制不保存真实窗口标题**
  - 决定：`tlctl record` 只有在标题命中 `.lens-dev.json` 白名单时才保留原文，此时 `meta.source = "self-chat"`，`window.title` 一律写成 `<self-chat>`。没命中时全部脱敏，`meta.source = "redacted-live"`，这类文件不能放进 fixtures/snapshots。
  - 理由：나와의 채팅 的标题是 Lipper 的昵称，fixtures 会进开源仓库。
  - 日期：2026-10-10
- **D-013 TalkLensCore 的几个实现取舍**
  - "Hangul 占比 ≥ 0.3"按**词**算，不按字母算：`Deadline은 Friday까지예요` 按字母只有 0.26，会被误判为不翻。占比低于阈值但含 Hangul 音节时，交给 `NLLanguageRecognizer` 决定。
  - URL、@提及不参与语言判断；只有 @提及的消息不翻。
  - Redactor 只有整串都是时间/日期标签（≤ 24 字）才保留原样，比旧探针更严。
  - TranscriptDiffer 用 id 集合一次扫描：中间某条被编辑或删除不算 reset，变化的 id 记进 `appended`。只有新旧完全没有共同 id 才算 reset。
  - `parseDividerDate` 要求整行就是日期（可带星期），避免把提到日期的普通消息当成分隔行。
  - 日期：2026-10-10
- **D-007 菜单栏用 NSStatusItem + AppKit 生命周期，不用 MenuBarExtra**
  - 决定：自定义 `main.swift` 加 `NSStatusItem`。浮动面板和设置/引导/关于窗口都由 AppKit 管理。
  - 理由：
    - `--self-check` 要在 NSApplication 启动前无 UI 运行。
    - LSUIElement 应用用 SwiftUI `Settings` scene 打开设置比较别扭。
    - 面板需要精细控制 level 和 collectionBehavior。
  - 面板 collectionBehavior = `[.canJoinAllSpaces, .fullScreenAuxiliary, .ignoresCycle]`：切到 KakaoTalk 所在 Space（含全屏）时面板已在；KakaoTalk 不在前台时隐藏，所以不会留在别的 Space。
  - 日期：2026-10-10
- **D-014 kmsg vendor 清单（@54cbff7）**

- **D-015 根据真机结构调整 kmsg 的解析规则（KakaoTalk 26.8.0）**
  - 气泡背景是包住 AXTextArea 的 AXImage，不算图片附件。
  - 时间标签只出现在同一分钟一组消息的最后一条上，所以时间和日期从下一条带标签的同侧消息**往回**填，kmsg 的往前延续只作为兜底。
  - 判断"我发的"先看气泡右缘是否贴近消息区右缘，比例阈值只作兜底：长气泡的中点比例约 0.6，落在 kmsg 的不确定区间里。
  - 日期分隔是一个没有文字的 AXButton，跳过。
  - 英文界面下 AXHelp 日期是美式短日期 `10/10/26`（M/D/YY），时间是 `6:01 PM`（窄不换行空格）。
  - 解析器默认只取与消息区可见范围相交的行（屏幕外的行也在 AX 树里）。bench 按全部行算，即最坏情况。
  - 日期：2026-10-10
- **D-016 开发期隐私规则放宽（Lipper 决定）**
  - 决定：Lipper 在 2026-10-10 明确表示，开发期间可以忽略"Claude 不能看到真实聊天内容"这条，只要不发消息、不删消息，因为真实聊天才是最真实的测试场景。所以开发和调试时，Lipper 发来的真实聊天截图、真实聊天窗口上的实测都可以用。
  - 仍然保持：
    1. 只读：不发送、不删除、不点击、不输入、不滚动。
    2. 仓库里不放任何真实聊天内容：fixtures/golden 仍然只有 self-chat 和合成数据，因为要开源。
    3. 产品本身的隐私设计不变：零网络、只在内存、日志不写原文。
  - 日期：2026-10-10
